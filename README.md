# MP-CRM — CRM для товарного бизнеса (WB / Ozon / Яндекс.Маркет + B2B)

## Что уже есть
`prisma/schema.prisma` — полная схема БД, покрывающая все модули:
товары, поставщики и сравнение цен, партии из Китая (с фиксацией курса
и ставки логистики на партию), себестоимость юнита по FIFO, листинги
на 3 маркетплейсах, остатки (свой склад + FBO/FBS), заказы, юнит-экономика.

## Почему не всё сразу в одном чате
Живая интеграция с API WB/Ozon/ЯМ требует:
- серверного хранения API-ключей (секреты, не должны попадать в клиентский код)
- регулярных фоновых синхронизаций (cron/webhook) остатков и заказов
- реального хостинга с базой данных

Это невозможно поднять и держать "живым" внутри чата — нужен деплой на
реальную инфраструктуру. План ниже даёт рабочую последовательность.

## Roadmap

### Шаг 1 — поднять БД и базовый CRUD (1-2 дня)
- `npx prisma migrate dev` — накатить схему на Postgres (Supabase/Railway — бесплатный тариф хватит для старта)
- Next.js API routes для CRUD: продукты, поставщики, партии, склады
- Простые формы для ручного ввода (пока без API-интеграций) — чтобы сразу
  перестать вести это в таблицах

### Шаг 2 — расчёт себестоимости и юнит-экономики
- Функция расчёта `UnitCost` при создании `BatchItem` (курс + логистика партии)
- FIFO-логика списания себестоимости при продаже
- Дашборд юнит-экономики по товару/площадке

### Шаг 3 — интеграции с API маркетплейсов
- `app/api/sync/wb` — синк остатков (`/api/v3/stocks`), заказов, комиссий (WB API)
- `app/api/sync/ozon` — Ozon Seller API (`/v3/product/info/stocks`, `/v3/posting/fbo/list`)
- `app/api/sync/ym` — Yandex Market API (Campaign API, `stocks`, `orders`)
- Ключи API — в переменные окружения (`.env`, никогда не в код)
- Cron (Vercel Cron / отдельный воркер) — синк остатков раз в N часов, заказов чаще

### Шаг 4 — сравнение поставщиков, дашборды, отчёты

## Стек
- Next.js (App Router) + TypeScript
- PostgreSQL + Prisma ORM
- Деплой: Vercel (app) + Supabase/Railway (Postgres)
